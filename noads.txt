! === Ad-tech the upstream lists under-block ===
! Mostly $important re-assertions over a domain-scoped @@ exception an upstream
! list carries, plus provider-level ad-tech that upstream blocks third-party-only
! and so misses when the publisher loads it first-party.
!
! 2026-07-04: EasyList carries a
! domain-scoped exception (easylist.txt, "@@||g.doubleclick.net/gpt/pubads_impl_
! $domain=accuweather.com|blastingnews.com|bloomberg.com|..." — ~20 publisher
! domains) that un-blocks Google Publisher Tag's ad-serving/bidding engine
! script specifically for those sites, while every other site still gets it
! blocked by the generic "||g.doubleclick.net^" rule. That upstream exception
! left a genuine, unfiltered ~36 KB ad-engine script loading full-size on
! accuweather.com (and every other listed domain). $important re-asserts the
! block over the upstream @@ exception; it does not touch the separate
! tag/js/gpt.js path (already handled by ubo-privacy.txt's $redirect stub) or
! any other g.doubleclick.net path, so gpt.js's own redirect/exception
! behaviour on these domains is unchanged by this rule.
||g.doubleclick.net/gpt/pubads_impl_$important

! === Anti-adblock walls ===
! Rules that keep a page readable when the publisher detects a blocker. Keyed on
! the wall VENDOR wherever possible, so one rule covers every site embedding it.
!
!
! 2026-07-04: anti-adblock-wall vendor network (html-load.com /
! content-loader.com / css-load.com / error-report.com). Observed on
! tomshardware.com (2026-07-04 non-clean row-by-row pass): an inline bootstrap
! loads html-load.com/lib.js, which pulls per-session obfuscated payloads from
! *.stg.html-load.com/session/<site>/... and rotating gibberish endpoints, renders
! ads in an html-load iframe, and — when it can't confirm ads rendered — replaces
! the article with a "Bitte erlauben Sie Werbung / Werbung zulassen" wall (support
! address @error-report.com, "Fehler: Error: Timeout"). Upstream lists barely cover
! it (only html-load.com $document,popup), so its fetch/document ad + detection
! loads were un-blocked. These are DEDICATED anti-adblock/ad-injection domains with
! no legitimate first-party use, so blocking the whole vendor is safe and GENERAL —
! keyed on the vendor, NOT on tomshardware.com, so it defeats this wall on every
! site that embeds this SaaS. Validated via CDP request-blocking on tomshardware:
! with the vendor hard-blocked the article renders fully (8/8 reloads) with no wall
! and no "can't load ads" fallback wall; lib.js never running means the wall's own
! timeout UI can't appear. (The gibberish rotating domains are downstream of lib.js,
! so blocking the stable infra domains stops them; live host A/B deferred to the
! next redeploy — the wall is server-side/intermittent and would not re-fire on
! demand during validation.)
||html-load.com^
||content-loader.com^
||css-load.com^
||error-report.com^

!
! 2026-07-05 (Ad-Shield realm-aware wall defeat): SUPERSEDES the
! earlier 2026-07-04e ##^script approach, which was REMOVED here because it TRIGGERS
! the wall instead of defeating it. Root cause, live-captured + deobfuscated on
! autobild.de (2026-07-05): the vendor (Ad-Shield / ad-shield.io) ships a first-party
!   <script id="<rand>" src="html-load.com/core.js" onload="<stage-1>" onerror="<stage-2>">
! whose onload/onerror attributes are SELF-CONTAINED, runtime-decoded watchdog stages.
! Each stage (a) BLANKS the page —
!   setInterval(()=>{document.body.remove();document.body.innerHTML=""},100) — using the
! MAIN-realm document, (b) builds a fullscreen error-report.com modal iframe, and (c)
! escalates confirm("Please allow ads")→ location.reload()/redirect where the reload is
! grabbed from an IFRAME realm (so a main-realm lock on `reload` can't reach it). It ALSO
! checks `document.querySelector("script#<id>")` and throws "Cannot find html-load script"
! (→ blank+modal) if the loader tag is gone — which is exactly why removing/serving-empty
! the tag walls the page. So we do NOT touch the tag. Instead a NoAds-authored, non-trusted
! scriptlet (`adshield.js`, deps: safe-self.fn; body in resources/local-scriptlets.json)
! runs at document-start on the vendor's publisher set and denies the wall the MAIN-realm
! primitives it needs: it makes document.body un-removable/un-blankable (survives re-hook),
! forces confirm/alert/prompt to a safe no-op so no escalation is armed, neutralizes
! location.reload()/report-host redirects, and keeps the report modal PRESENT-but-invisible
! (so the vendor's own 1s visibility check passes and never fires the reload escalation).
! The iframe-realm reload is never reached because the escalation is starved of a trigger.
! Validated in a DIRECT Chrome with NoAds' network blocking replicated, POST-CONSENT, 6/6
! reloads CLEAN (full article renders, ad-free, no wall/blank/redirect, zero dialogs) on
! autobild.de and computerbild.de. Scoped to the known Ad-Shield publisher set (keeps the
! body/dialog structural locks off unrelated sites). Pairs with the ||html-load.com^ etc.
! network blocks above.
autobild.de,computerbild.de,bild.de,tomshardware.com##+js(adshield, error-report.com)

!
! bild.de also gates a SERVER-SIDE wall: the homepage/article HTML embeds a config flag
! "adBlockWallEnabled":true and its own first-party JS redirects to bild.de/adblockwall.html
! ("Aufgrund Ihres Blockers zeigen wir BILD.de nicht an") when an adblocker is detected.
! That decision is made from a server-rendered flag the scriptlet can't reach; the flip is
! done in the response bytes by the $replace rule ALREADY carried in ubo-filters.txt:
!   ||bild.de^$doc,replace=/"adBlockWallEnabled":true/"adBlockWallEnabled":false/
! (parsed by noads-rewrite/src/replace.rs; unit-tested there). GAP-4 re-validated it live:
! with the flag flipped bild.de renders the real homepage ("Aktuelle Nachrichten | BILD.de"),
! 6/6 reloads, no adblockwall.html. Not duplicated here — noting the dependency only.
!
! 2026-07-05 (bild wall regression — non-trusted layer restoration): the
! 2026-07-05 review engine found bild.de STILL walls in a real fresh-profile browser, because
! the $replace above only reaches the flag if it's in the RAW document body, but modern bild
! sets it in a runtime hydration state. uBO layers a SCRIPTLET fix on top —
! `bild.de##+js(rpnt, script, "adBlockWallEnabled":true, …false)` (rewrite the inline
! hydration <script> text) — but `rpnt` is the alias of `replace-node-text` and that alias is
! NOT in our vendored resources, so uBO's rule silently no-ops. uBO's fourth layer,
! `##+js(trusted-replace-argument, JSON.parse, …)`, is deliberately unavailable — NoAds drops
! every trusted-* scriptlet (scriptlet_transform.rs; NoAds_Plan.md §426). So we re-assert the
! inline-script layer with the CANONICAL, vendored, NON-trusted scriptlet name — same effect,
! no alias dependency, no pin bump, no trusted permission. Pairs with the already-synced uBO
! `json-prune` layer (CLIENT_STORE_INITIAL_STATE…adBlockWallEnabled). Live wall→no-wall A/B on
! the next redeploy; if the flag proves unreachable by all three non-trusted layers, a
! NoAds-authored bild-specific JSON.parse-hook local scriptlet is the fallback (not shipped
! unless measured necessary).
bild.de##+js(replace-node-text, script, "adBlockWallEnabled":true, "adBlockWallEnabled":false)

!
! 2026-07-09 (bild wall — SECOND, flag-INDEPENDENT path: loader_light integrity
! redirect). A 50-site real-Chrome (--attach :8080) iteration-1 sweep (tools/site-verify run
! gap-iter1-2026-07-09) found bild.de STILL walls even though the adBlockWallEnabled flag IS now
! flipped to false in the served bytes (confirmed by fetching the homepage through :8080 — the three
! flag layers above work). Root cause, decoded from browser.log + session.har + the served HTML: the
! wall has a second trigger that has nothing to do with the flag. bild loads
!   <script src="https://html-load.com/sdk.js" onload="(async()=>{…})()" onerror="(async()=>{…})()">
! NoAds serves sdk.js as an empty 200 stub (||html-load.com^ above). The inline handler runs a
! postMessage handshake with the (now-dead) SDK; it fails, so the handler throws "Failed to load
! website properly since html-load.com is tainted" and runs a destroy function that:
!   (a) setInterval(()=>document.body.remove(), 100)          — continuously BLANKS the page,
!   (b) fetch('https://error-report.com/report?type=loader_light_redirect…')  — already blocked,
!   (c) o.href = 'https://www.bild.de/adblockwall.html'        — navigates to the WALL.
! The adshield scriptlet's runtime body-freeze loses the timing race to (a)/(c). Both the onload and
! onerror destroy functions begin with the byte-identical prefix `=async function(X){try{try{
! localStorage.setItem`; injecting an early `return;` right after the opening brace neutralizes the
! blank + report + redirect at the SOURCE (in the response bytes, before any of it runs), leaving the
! already-rendered homepage intact. A static body rewrite beats the runtime scriptlet timing race for
! this trigger and is flag-independent. Unit-tested in noads-rewrite/src/replace.rs
! (neutralizes_bild_loader_light_redirect + real_noads_local_bild_loader_rule_parses_and_applies).
! VALIDATED 2026-07-10 in the scoped dev-worker sandbox (noads-worker run --scoped --port 8081, mints via
! the installed broker) with real Chrome over CDP-attach: 3/3 fresh-profile runs land on bild.de/ ("Aktuelle
! Nachrichten | BILD.de", homepage renders behind the normal consent CMP), zero navigations to
! /adblockwall.html -- vs the pre-fix redirect. NB the adBlockWallEnabled layers above are IRRELEVANT to real
! browsers: bild serves adBlockWallEnabled:false NATIVELY to a real Chrome fingerprint (only curl/bots get
! :true), so this loader_light destroy-fn is the SOLE real-browser wall trigger. Scoped to bild.de $doc.
! Production MSI redeploy pending (dev-sandbox-proven).
||bild.de^$doc,replace=/(=async function\([a-z]\)\{)(try\{try\{localStorage\.setItem)/${1}return;${2}/

! === First-party and native ad slots ===
! Cosmetic rules for ad slots served from the publisher's own domain, which
! network rules cannot reach. Each was confirmed against a live render.
!
!
! 2026-07-05: gaps from a 47-site real-browser adgap sweep (consent
! accepted, banner-verified screenshots). NoAds blocked ~everything; these are the
! evidence-backed, PROVIDER-LEVEL (not per-site) gaps that survived.
!
! 2026-07-10 (Burda "Quadro" — network block RETRACTED, replaced by cosmetic
! rules). The old rule here was `||quadro.burda-forward.de^`, justified as "the Burda ad
! server … No breakage risk". That was WRONG: quadro.burda-forward.de is Burda's shared
! IMAGE CDN and serves editorial photos and native-ad creatives over the SAME url shape
! (`/ctf/<uuid>.<uuid>.jpeg?im=Region…`), same resource type, same sizes. Blocking the host
! makes NoAds answer 200 with a zero-byte body, so every <img> decodes to naturalWidth 0.
! Measured through the deployed worker vs DIRECT (2026-07-10): focus.de 3 broken / 0 direct
! (incl. the lead photo), chip.de 14 broken / 0 direct. Editorial images served by quadro on
! one page load: chip.de 163, focus.de 47, bunte.de 378. No path/type/size discriminator
! exists, so no network rule — and no `@@…$image` exception — can separate the ads from the
! photos. The ads are first-party-served native "Anzeige" teasers, so the correct instrument
! is cosmetic hiding of the teaser element.
!
! Markers below were measured DIRECT on live homepages (matched / sponsored / editorial),
! "sponsored" = the container owns a leaf text node reading exactly "Anzeige"/"Werbung":
!   chip.de   article:has(div.RUC-Badge--Secondary)          13 / 13 / 0  (of 167 articles)
!   bunte.de  article:has(div.RUC-TeaserBadge-Ad)            14 / 14 / 0
!   focus.de  article.StageCarousel-Item--FixedTeaserSlot    12 / 12 / 0
!   chip.de   article.StageCarousel-Item--FixedTeaserSlot     8 /  8 / 0
!   focus.de  article.BlockItem--Article--FixedTeaserSlot     5 /  5 / 0
! Both badges' own text is exactly "Anzeige" — Burda's design system labels the ad itself, so
! this is a marker by construction, not an inference. The badge class name differs per title
! (design-system drift), hence separate rules; hiding the badge alone would leave the ad
! standing, so the rule climbs to the <article>. Never key on the bare carousel/teaser class:
! `article.StageCarousel-Item` matches 127 on focus.de, of which 115 are editorial.
! The focus.de rules duplicate adguard-german.txt:1690+ on purpose — we broke these pages, so
! the repair must not depend on a third-party list keeping a matching rule.
! tvspielfilm.de and cinema.de make ZERO quadro requests (the old comment's "whole publisher
! family" claim was overstated); finanzen100.de was observed serving only editorial from it.
chip.de##article:has(div.RUC-Badge--Secondary)
bunte.de##article:has(div.RUC-TeaserBadge-Ad)
chip.de,focus.de##article.StageCarousel-Item--FixedTeaserSlot
focus.de##article.BlockItem--Article--FixedTeaserSlot

! === Surrogate redirects ===
! Neutered stand-ins for tracker scripts whose absence breaks the page.
!
!
! 2026-07-30: surrogate redirects for two trackers that had NO stub at all.
!
! NoAds answers a blocked request with a synthetic `200 OK` + empty body
! (NoAds answers a blocked request with a synthetic response — a 4xx
! or a network-level failure would produce browser error pages and is itself an
! anti-adblock detection signal). A 200 makes a <script> element fire `load`,
! NOT `error`. Both bootstraps below install their initialisation INSIDE that
! onload handler, so with no stub the callback runs against a global that was
! never defined and the page throws:
!
!   bat.bing.com/bat.js        -> `ReferenceError: UET is not defined`
!                                 (filehippo.com x7 runs, softonic.com, wsj.com)
!   *.imrworldwide.com/v60.js  -> `ReferenceError: nol_t is not defined`
!                                 (wsj.com, via Tealium's Nielsen tag)
!
! Under an extension blocker the request fails at the network layer, `onerror`
! fires, and neither throw happens — i.e. this error class is manufactured by the
! proxy block style, which is why the fix is a redirect-to-stub rather than a
! change to the block path. Redirecting instead of blocking sends the SAME zero
! tracking data: every stub method is a no-op and no request leaves the browser.
! Stub bodies are NoAds-authored surrogates.
! (noads_bing_uet.js / noads_nielsen.js), NoAds-authored — uBO has no equivalent.
||bat.bing.com/bat.js$script,redirect=noads_bing_uet.js
||imrworldwide.com/v60.js$script,redirect=noads_nielsen.js

! === Unbreak ===
! Narrow exceptions where a block above (or upstream) broke real functionality.
!
!
! 2026-07-22: NoAds' own change broke
! these, so unbreaking them is the
! blocker's own responsibility.
!
! A 2026-07-22 change gave iframe requests their own `ContentType::Subdocument` instead of
! folding them into `Other`. Upstream carries a small number of `$other`-scoped
! EXCEPTION rules that were, in practice, exempting IFRAMES — they only worked
! because every iframe used to land in the `Other` bucket. Now that those
! requests are typed `subdocument`, the `$other` exceptions no longer apply and
! the frames get blocked, which is the un-blocking/page-breakage direction the
! ticket's LOST-blocks analysis was meant to surface.
!
! Both cases below were CONFIRMED on the live 0.1.3 install, not inferred: the
! request returns a 0-byte synthetic when sent with `sec-fetch-dest: iframe`
! and the real upstream body without it. These two mirror the upstream
! exceptions with the now-correct type so behaviour returns to what the
! upstream list authors intended. They are deliberately narrow — same host,
! same path shape, same `domain=` scope as the upstream rule; no new site is
! exempted, and the ad itself is still blocked everywhere the upstream rule
! did not exempt it.
!
! Only these two of the 17 `$other`-scoped rules in the shipped lists needed it;
! the rest either list `subdocument` explicitly already or cover
! media/xhr/script requests that never took the iframe path.
!
! ubo-unbreak.txt: "@@||tpc.googlesyndication.com/safeframe/*/container.html$other,domain=abola.pt"
@@||tpc.googlesyndication.com/safeframe/*/container.html$subdocument,domain=abola.pt

@@||ad3.adfarm1.adition.com^$subdocument,domain=servustv.com
